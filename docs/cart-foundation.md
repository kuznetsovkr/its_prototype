# Корзина — хранение и список изделий

## Что готово

Серверное хранение отдельных изделий с параметрами вышивки, комментариями,
количеством и фотографиями. В браузере хранится только доступ к гостевой корзине
(`its_cart_access_v1` в localStorage), не файлы, цены и не данные получателя.
`CartProvider` подключён к приложению, `useCart` предоставляет операции загрузки,
добавления, изменения количества, удаления, очистки и восстановления файлов изделия.
При обычном посещении без сохранённого доступа корзина на сервере не создаётся.

Срок согласован пользователем: **30 дней после последнего изменения**. Чтение
корзины не продлевает срок. После истечения сервер закрывает доступ и удаляет
корзину с фотографиями. Очистка данных браузера/приватный режим могут удалить
доступ раньше; переноса между устройствами без отдельного сценария нет.

Фотографии доступны только владельцу через контроллер с заголовком доступа;
для показа/восстановления их нужно получить как Blob, а не подставлять закрытый
URL прямо в `<img>`. `restoreItem` возвращает реальные File, привязанные к нужному
изделию. Цены и профиль одежды после восстановления нужно получать из актуального
каталога, а не доверять сохранённому браузерному состоянию.

Изменения сериализуются. В браузерах с Web Locks операции разных вкладок также
сериализуются; изменение localStorage уведомляет соседние вкладки. При сетевой
ошибке доступ не удаляется. Истечение срока определяет сервер, не часы клиента.

## Добавление изделия

1. После корректного заполнения изделия и фото создать стабильный `requestKey`
   через `createCartItemKey()`. Сохранять его до подтверждённого добавления;
   повтор запроса использует тот же ключ и не дублирует изделие.
2. В `addItem` передать снимок OrderContext (`clothing`, `embroidery`, согласие
   `recipient.privacyConsent`) и свежий токен текущего Turnstile.
3. Создание гостевой корзины и её первая загрузка используют одну проверку
   Turnstile в течение 5 минут. Последующие новые изделия требуют свежей проверки.
   После операции сбрасывать виджет, как при существующем оформлении.
4. Сбрасывать текущее изделие и переходить на первый этап **только после успеха**.
   При ошибке сохранять выборы и исходные File. Общие данные получателя не очищать.
5. Пока цена не известна (`custom`, включая надпись), оставлять отдельную заявку:
   такие изделия не смешиваются с оплачиваемой корзиной.

## Итерация 2: четвёртый этап

«Добавить в корзину» сохраняет готовое изделие с фото и возвращает к выбору
следующего. Нужны корректная конфигурация, фотографии, согласие и проверка защиты;
заполнять доставку/контакты ради одного добавления не обязательно. После успеха
очищается только конструктор, общие поля покупателя/доставки сохраняются.
При ошибке File остаются в памяти. `cartItemKey` сохраняется в sessionStorage;
повтор с тем же содержимым не создаёт дубля. Изменение выбора создаёт новый ключ,
пересчёт цены/обновление профиля без изменения выбора — нет. Если ответ потерян,
загрузка корзины сверяет ключ и подтверждает сохранение даже после перезагрузки.

По Figma `191:28` список показывает реальные товары, тип и количество объектов
вышивки, цвет, размер. Чёрные кружки **декоративные**, это не выбор оплачиваемых
позиций. Количество одежды и удаление работают через защищённый API; ошибки
не меняют показанное количество, состояние соседних вкладок обновляется.
Цены сохранённых изделий рассчитываются сервером заново. Предварительная сумма
не включает доставку и ещё не добавленное текущее изделие; это явно подписано.
Недоступные позиции остаются видимыми и удаляемыми, неполная сумма не показывается.

На первом этапе есть ссылка на сохранённые изделия: `/recipient?cart=1`.
Этот режим открывается и без активного конструктора. Popup из шапки не придуман;
иконка корзины пока сохраняет прежний переход на первый этап. Пока нет общей оплаты,
при непустой корзине прежняя оплата одного изделия отключена с пояснением —
состав не должен незаметно теряться при оплате. В режиме списка выбор доставки
и сертификат также отключены до группового расчёта. При пустой корзине прежний
одиночный заказ работает. Индивидуальная заявка остаётся отдельной с явным
пояснением, что сохранённые изделия в неё не входят.

Изделие с незавершённым конструктором пока не добавляется автоматически только
за выбор типа/цвета/размера; фотографии до подтверждённого добавления не сохранены
на сервере. Автосохранение таких черновиков — отдельный оставшийся шаг корзины.

## Следующие итерации

- Единый серверный расчёт, общая доставка, атомарные резервы, одна оплата,
  применение сертификата к изделиям, перенос фото в оформленный заказ.
- Многопозиционные заказы в админке и Telegram, проверки полного пути.
- Pop-up из шапки — после отдельного макета.

Не возвращать «Город» из макета;
сохранить уже реализованный телефон другого получателя. Не подставлять макетные
товары/суммы и не смешивать индивидуальную заявку с онлайн-оплатой.

## Проверки

`npm test`, `npm run lint`, `npm run lint:styles`, `npm run build`.
`npm run test:e2e:cart`: браузерная проверка ядра и настоящих страниц
RecipientDetails/OrderPage на тестовом потребителе React, включая новый сеанс,
две вкладки, реальные File, количество/удаление, сетевую ошибку и срок,
повтор после потерянного ответа, восстановление, клавиатуру и адаптивную геометрию
320–1920px. Проверяется Chromium desktop/mobile и WebKit mobile.
Тестовый экран находится в `e2e/fixtures`, не включён в production-сборку.
Реальный API, PostgreSQL, безопасность и миграции проверяются в backend через
`npm run test:migrations`. Деплой — только по отдельному запросу.
