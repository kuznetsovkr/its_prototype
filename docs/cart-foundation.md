# Корзина — хранение, список изделий и общая оплата

## Панель корзины в шапке

Иконка открывает панель справа на всю высоту окна (Figma `163:128`, `165:250`).
На телефоне ширина ограничена экраном; отдельного мобильного кадра в переданных ссылках нет.
На десктопе/планшете иконка видна при наличии сохранённых изделий или полного первого этапа
конструктора, на телефоне доступна и пустая корзина. Панель переиспользует серверную корзину,
список изделий и штатные операции количества/удаления; просмотр не создаёт корзину и не
продлевает её хранение. Текущий черновик не дублируется после подтверждённого сохранения.
Незавершённое изделие не входит в цену и блокирует оформление до завершения/удаления.
Закрытие: крестик, фон, Escape. Фокус удерживается в панели и возвращается к кнопке;
страница под панелью недоступна для взаимодействия и заблокирована от прокрутки.
Счётчик у иконки складывает количество сохранённых единиц и одно незавершённое изделие;
принятый сервером черновик не считается дважды. Центральная подсказка со ссылкой
«У вас есть сохранённые изделия / Открыть корзину» удалена.

## Что готово

Серверное хранение отдельных изделий с параметрами вышивки, комментариями,
количеством и фотографиями. Доступ к серверной корзине хранится в браузере
(`its_cart_access_v1` в localStorage), не файлы, цены и не данные получателя.
Отдельный локальный черновик конструктора описан в итерации 4 ниже.

Постоянная подсказка о сроке хранения/повторном выборе фото и отдельная кнопка
«Удалить черновик» убраны по обратной связи. Сообщения о реальных ошибках сохранения
и предупреждение о потерянных после перезагрузки файлах сохранены; сам механизм
хранения не меняется. В корзине остаётся штатное удаление незавершённого изделия.
`CartProvider` подключён к приложению, `useCart` предоставляет операции загрузки,
добавления, изменения количества, удаления, очистки и восстановления файлов изделия.
При обычном посещении без сохранённого доступа корзина на сервере не создаётся.

Срок согласован пользователем: **30 дней после последнего изменения**. Чтение
корзины не продлевает срок. После истечения сервер закрывает доступ и удаляет
корзину с фотографиями. Очистка данных браузера/приватный режим могут удалить
доступ раньше; переноса между устройствами без отдельного сценария нет.

Фотографии доступны только владельцу через контроллер с заголовком доступа;
для показа/восстановления их нужно получить как Blob, а не подставлять закрытый
URL прямо в `<img>`. `restoreItem` возвращает реальные File, привязанные к нужному
изделию. Цены и профиль одежды после восстановления нужно получать из актуального
каталога, а не доверять сохранённому браузерному состоянию.

Изменения сериализуются. В браузерах с Web Locks операции разных вкладок также
сериализуются; изменение localStorage уведомляет соседние вкладки. При сетевой
ошибке доступ не удаляется. Истечение срока определяет сервер, не часы клиента.

## Добавление изделия

1. После корректного заполнения изделия и фото создать стабильный `requestKey`
   через `createCartItemKey()`. Сохранять его до подтверждённого добавления;
   повтор запроса использует тот же ключ и не дублирует изделие.
2. В `addItem` передать снимок OrderContext (`clothing`, `embroidery`, согласие
   `recipient.privacyConsent`) и свежий токен текущего Turnstile.
3. Создание гостевой корзины и её первая загрузка используют одну проверку
   Turnstile в течение 5 минут. Последующие новые изделия требуют свежей проверки.
   После операции сбрасывать виджет, как при существующем оформлении.
4. Сбрасывать текущее изделие и переходить на первый этап **только после успеха**.
   При ошибке сохранять выборы и исходные File. Общие данные получателя не очищать.
5. Пока цена не известна (`custom`, включая надпись), оставлять отдельную заявку:
   такие изделия не смешиваются с оплачиваемой корзиной.

## Итерация 2: четвёртый этап

«Добавить в корзину» сохраняет готовое изделие с фото и возвращает к выбору
следующего. Нужны корректная конфигурация, фотографии, согласие и проверка защиты;
заполнять доставку/контакты ради одного добавления не обязательно. После успеха
очищается только конструктор, общие поля покупателя/доставки сохраняются.
При ошибке File остаются в памяти. `cartItemKey` сохраняется в sessionStorage;
повтор с тем же содержимым не создаёт дубля. Изменение выбора создаёт новый ключ,
пересчёт цены/обновление профиля без изменения выбора — нет. Если ответ потерян,
загрузка корзины сверяет ключ и подтверждает сохранение даже после перезагрузки.

По Figma `191:28` список показывает реальные товары, тип и количество объектов
вышивки, цвет, размер. Чёрные кружки **декоративные**, это не выбор оплачиваемых
позиций. Количество одежды и удаление работают через защищённый API; ошибки
не меняют показанное количество, состояние соседних вкладок обновляется.
Цены сохранённых изделий рассчитываются сервером заново. Предварительная сумма
не включает доставку и ещё не добавленное текущее изделие; это явно подписано.
Недоступные позиции остаются видимыми и удаляемыми, неполная сумма не показывается.

На первом этапе есть ссылка на сохранённые изделия: `/recipient?cart=1`.
Этот режим открывается и без активного конструктора. Popup из шапки не придуман;
иконка корзины пока сохраняет прежний переход на первый этап. При пустой корзине прежний
одиночный заказ работает. Индивидуальная заявка остаётся отдельной с явным
пояснением, что сохранённые изделия в неё не входят.

Незавершённое изделие хранится отдельно от готовых серверных позиций (итерация 4).
Фотографии до подтверждённого добавления не сохранены на сервере.

## Итерация 3: один заказ и один платёж

- `/recipient?cart=1` оформляет весь сохранённый состав на одного получателя.
  Если есть новое готовое изделие, «подтвердить состав» сначала сохраняет его в корзину.
  Затем показываются окончательный состав и общий расчёт; оплата требует отдельного
  нажатия. Новое изделие не исключается молча.
- Общая онлайн-оплата пока только с ПВЗ СДЭК. Согласованная упаковка: **каждая единица
  одежды — отдельное место** с серверными габаритами и весом. Почта/самовывоз остаются
  в прежнем отдельном сценарии заявки до согласования стоимости доставки.
- Клиент передаёт ревизию корзины, код ПВЗ, сертификат, контакты и хеш расчёта, но не цены.
  Изменившийся расчёт нужно подтвердить заново. Сервер одновременно резервирует все
  остатки и баланс одного сертификата. Сертификат покрывает изделия с вышивкой, не доставку.
- На время оплаты состав и поля заблокированы. После закрытия страницы корзина
  возвращает тот же заказ: повторная кнопка продолжает один счёт, не создаёт новый.
  Потерянный сетевой ответ сверяется с сервером.
- «Отменить оформление и изменить корзину» освобождает резервы, оставляет изделия/фото.
  Старую ссылку после отмены оплачивать нельзя; запоздалая оплата требует проверки менеджером.
- После подтверждённой оплаты очищается только оплаченный состав. Фотографии заказа —
  независимые закрытые копии; истечение 30-дневной корзины их не удаляет.
- Telegram и API заказа передают все позиции и привязанные фото. Отдельного интерфейса
  управления заказами в админке пока нет.

## Итерация 4: автосохранение незавершённого изделия

- После выбора типа одежды, цвета и размера автоматически сохраняется один активный
  черновик в `its_constructor_draft_v1` (localStorage). Срок — 30 дней с последнего
  изменения выбора/текстов, не с открытия страницы. Без полного первого этапа новый
  черновик не создаётся. Выборы и тексты восстанавливаются после закрытия браузера.
- Это **не готовая серверная позиция**: нет резерва, цены или автоотправки заявки.
  До согласия/CAPTCHA файлы не загружаются. Сохраняются только выборы конструктора,
  тексты и метаданные потерянных File для уведомления; контакты, адреса, согласие,
  сертификат и токены заказа остаются вне постоянного черновика.
- Каталог/профили/цены не переносятся из localStorage. На первом этапе они загружаются
  заново; недоступный товар нельзя продолжить. Сетевая ошибка каталога не стирает выбор.
- В списке корзины незавершённое изделие подписано отдельно, без цены и количества.
  Перед оплатой его нужно завершить или явно удалить, чтобы оно не потерялось молча.
  Удаление черновика не меняет готовые серверные изделия. При наличии File требуется
  подтверждение удаления; после восстановления показывается просьба загрузить фото заново.
- После добавления/оформления/успешного заказа черновик снимается. Потерянный ответ
  сохранения сверяется по `cartItemKey` даже после закрытия браузера; дубль не создаётся.
- Старая вкладка не перезаписывает обнаруженную новую ревизию: автосохранение
  приостанавливается с предупреждением, без сброса текущих File. Запись-снятие оставляет
  небольшой tombstone, а sessionStorage помечается ревизией — старый сеанс не возрождает
  завершённое/удалённое изделие. Одновременная запись в один момент остаётся локальным
  last-writer-wins; это не финансовое хранилище. Очистка данных сайта удаляет черновик.
- Если localStorage заблокирован/переполнен, показывается ограничение; оформление
  в памяти и прежний sessionStorage продолжают работать. Не требуется создавать
  серверную корзину без согласия покупателя или ослаблять Turnstile для автосохранения.

## Оставшиеся шаги

- Pop-up из шапки — после отдельного макета.
- Правила оплаты Почты России/самовывоза — после согласования, см. `delivery-decisions.md`.

Не возвращать «Город» из макета;
сохранить уже реализованный телефон другого получателя. Не подставлять макетные
товары/суммы и не смешивать индивидуальную заявку с онлайн-оплатой.

## Проверки

`npm test`, `npm run lint`, `npm run lint:styles`, `npm run build`.
`npm run test:e2e:cart`: браузерная проверка ядра и настоящих страниц
RecipientDetails/OrderPage на тестовом потребителе React, включая новый сеанс,
две вкладки, реальные File, количество/удаление, сетевую ошибку и срок,
повтор после потерянного ответа, восстановление, клавиатуру и адаптивную геометрию
320–1920px. Проверяется Chromium desktop/mobile и WebKit mobile.
Дополнительно: общий платёж, повторное открытие оплаты, потерянный ответ, безопасная
отмена, сертификат без доплаты и изоляция прежнего одиночного счёта от новой корзины.
Автосохранение: новый сеанс браузера без sessionStorage, тексты/выборы/метаданные фото,
просроченный черновик, устаревшая вкладка, блокировка хранилища, безопасное удаление,
невозможность оплатить незавершённый состав и восстановление потерянного ответа загрузки.
PayKeeper/СДЭК имитируются; реальная банковская операция не выполняется.
Тестовый экран находится в `e2e/fixtures`, не включён в production-сборку.
Реальный API, PostgreSQL, безопасность и миграции проверяются в backend через
`npm run test:migrations`. Деплой — только по отдельному запросу.
