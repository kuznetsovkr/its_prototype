# Корзина — итерация 1: хранение

## Что готово

Серверное хранение отдельных изделий с параметрами вышивки, комментариями,
количеством и фотографиями. В браузере хранится только доступ к гостевой корзине
(`its_cart_access_v1` в localStorage), не файлы, цены и не данные получателя.
`CartProvider` подключён к приложению, `useCart` предоставляет операции загрузки,
добавления, изменения количества, удаления, очистки и восстановления файлов изделия.
При обычном посещении без сохранённого доступа корзина на сервере не создаётся.

Срок согласован пользователем: **30 дней после последнего изменения**. Чтение
корзины не продлевает срок. После истечения сервер закрывает доступ и удаляет
корзину с фотографиями. Очистка данных браузера/приватный режим могут удалить
доступ раньше; переноса между устройствами без отдельного сценария нет.

Фотографии доступны только владельцу через контроллер с заголовком доступа;
для показа/восстановления их нужно получить как Blob, а не подставлять закрытый
URL прямо в `<img>`. `restoreItem` возвращает реальные File, привязанные к нужному
изделию. Цены и профиль одежды после восстановления нужно получать из актуального
каталога, а не доверять сохранённому браузерному состоянию.

Изменения сериализуются. В браузерах с Web Locks операции разных вкладок также
сериализуются; изменение localStorage уведомляет соседние вкладки. При сетевой
ошибке доступ не удаляется. Истечение срока определяет сервер, не часы клиента.

## Контракт для следующей итерации

1. После корректного заполнения изделия и фото создать стабильный `requestKey`
   через `createCartItemKey()`. Сохранять его до подтверждённого добавления;
   повтор запроса использует тот же ключ и не дублирует изделие.
2. В `addItem` передать снимок OrderContext (`clothing`, `embroidery`, согласие
   `recipient.privacyConsent`) и свежий токен текущего Turnstile.
3. Создание гостевой корзины и её первая загрузка используют одну проверку
   Turnstile в течение 5 минут. Последующие новые изделия требуют свежей проверки.
   После операции сбрасывать виджет, как при существующем оформлении.
4. Сбрасывать текущее изделие и переходить на первый этап **только после успеха**.
   При ошибке сохранять выборы и исходные File. Общие данные получателя не очищать.
5. Пока цена не известна (`custom`, включая надпись), оставлять отдельную заявку:
   такие изделия не смешиваются с оплачиваемой корзиной.

**На сайте кнопка «Добавить в корзину» пока остаётся неактивной.** Нового списка,
pop-up, групповой оплаты, списания сертификата и резервов в этой итерации нет.
Существующий одиночный заказ и его sessionStorage-черновик работают как раньше;
фото незавершённого конструктора пока не становятся сохранёнными автоматически.

## Проверки

`npm test`, `npm run lint`, `npm run lint:styles`, `npm run build`.
`npm run test:e2e:cart`: браузерная проверка ядра на отдельном тестовом потребителе
React, включая новый сеанс, две вкладки, настоящие File, сетевую ошибку и срок.
Тестовый экран находится в `e2e/fixtures`, не включён в production-сборку.
Реальный API, PostgreSQL, безопасность и миграции проверяются в backend через
`npm run test:migrations`. Деплой — только по отдельному запросу.
